# Zorid working agreements

## Execution
- Parallelize independent, easily separable work with native Codex subagents when it improves throughput. Give each agent bounded file ownership and acceptance checks; integrate and verify in the primary agent. Keep dependent steps sequential and avoid duplicate exploration.
- Keep the Mac light: development, dependencies, tests, and JavaScript exports run on WSL. iOS compilation/signing runs on GitHub macOS runners. Produce downloadable artifacts.
- Use Bun and commit the lockfile. Track implementation in Git with small, reviewable commits.
- Commit messages start with the reason for the change. Add Lore trailers when useful: Constraint, Rejected, Confidence, Scope-risk, Directive, Tested, Not-tested.

## Product boundaries
- Native-rendered React Native/Expo application with feature routes and a permanent Settings tab.
- Devices receive whole-library JS releases directly from a paired user's host. No EAS hosting requirement. New native capabilities require a binary rebuild.
- Keep code deployment separate from personal-data access. Pairing credentials, signing material, provisioning profiles, private metadata, and .env files never enter Git or public logs.
- Local-first shared records are the foundation. PowerSync and Yjs remain candidates until integration is validated; never present mock synchronization as working sync.
- Before product/UI changes, read DESIGN.md. Before architecture/deployment work, read docs/architecture.md and docs/ios-builds.md when present.

## Expo and verification
- Check installed Expo versions and matching official documentation before using APIs; verify against installed types.
- Native projects are generated by Expo prebuild. Put durable configuration in app.config.ts or config plugins.
- Run targeted tests, typecheck, lint, and iOS JS export before claiming the foundation works. CI builds verify native compilation. State device-only validation gaps explicitly.
- Keep public artifacts free of secrets, private profiles, and personal data. Signed IPAs should be retained as Actions artifacts rather than public release assets by default.
