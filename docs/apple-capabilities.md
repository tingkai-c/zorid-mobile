# Apple capabilities for deployed apps

Research checked 2026-11-12 against Apple's public documentation, [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/), React Native 0.88 documentation, and this checkout's installed types. This is a capability and implementation catalog, not a claim that every proposed bridge is implemented or shipped.

## Delivery boundary

An OTA release can call native APIs already compiled into its compatible Zorid binary. New native modules, Info.plist permission descriptions, entitlements, URL registrations, and extensions require a binary rebuild and runtime compatibility change; see [architecture](architecture.md) and [iOS builds](ios-builds.md). Native availability, hardware support, OS version, authorization, and execution context are separate checks.

The runtime 4 baseline includes `expo-camera`, `expo-secure-store`, `expo-linking`, `expo-widgets`, SQLite and Crypto. `expo-file-system` 58.0.13 is already installed transitively and Apple-autolinked; runtime 5 promotes that existing version to a direct dependency for its public SDK. See [package.json](../package.json). Installed RN Share/Linking, SecureStore, Camera and FileSystem types/source confirm these entry points. Packages listed below as optional alternatives are not assumed installed merely because Expo documents them.

Runtime 5 implementation is in progress: `ZoridDevice` adds clipboard, photo picking/saving, authentication, local notifications/categories/response delivery, and calendar/reminders; the haptics bridge adds advanced haptic-only patterns/playback. SDK 58 Location, Contacts, Audio, Sensors, Battery, Network, Device and Print are now installed for runtime 5, reusing their official native bridges instead of duplicating them in Swift. **These changes are not shipped until native CI compilation and delivery are confirmed; device acceptance remains separate.** The catalog identifies this work without claiming every public Apple operation is exposed.

## Practical API catalog

**Existing** means provided by RN, an installed/autolinked Expo dependency, or the documented local Zorid module. **In progress (5)** names the planned runtime 5 bridge; **Addition** names later unimplemented coverage. Both need a compatible binary before deployed code can use them. Framework names identify implementation options; it does not imply unrestricted framework access.

UIKit activity sheets can extend file sharing. [RN Share](https://reactnative.dev/docs/share), [RN Linking](https://reactnative.dev/docs/linking). | No general data-access prompt for sharing text or opening Settings. App-scheme queries need `LSApplicationQueriesSchemes`; receiving new schemes/universal links requires binary configuration. `openSettings` opens this app's settings, not arbitrary private Settings pages. Opening mail/SMS/phone UI does not silently send or call. |

Prefer explicit paste or Apple's control; do not poll the clipboard. No Info.plist usage string substitutes for that approval. |

Underlying in-place document access needs security-scoped resources and coordinated I/O; a saved path alone is insufficient. SecureStore biometric-set changes can invalidate protected items; app-unlock UI alone does not encrypt records. Namespacing must keep feature secrets separate from shell pairing credentials. |

Local scheduling needs no APNs service or push entitlement. Register categories, handle cold-start responses, and distinguish foreground actions from native/background handlers. A queued response preserves an interaction for consumption; it does not itself run a mutation. Background mutation needs a compiled handler or validated durable-action route; an ordinary React listener does not establish terminated-app execution. Remote push and custom notification extensions are separate additions. |
| Camera and photo selection | **Existing:** Expo Camera preview, photos, video and barcode scanning. **In progress (5):** system photo picker and add-only photo saving through `ZoridDevice`. **Addition:** broader library management through PhotoKit or uninstalled `expo-media-library`. [SDK 58 Camera](https://docs.expo.dev/versions/v58.0.0/sdk/camera/), [Apple photo picker](https://developer.apple.com/documentation/photokit/selecting-photos-and-videos-in-ios). | Camera needs `NSCameraUsageDescription` and approval. Saving only can use add-only Photos access; browsing/editing the library requires the appropriate PhotoKit authorization and limited-library handling. |

## SDK 58 foreground configuration

Installing a module does not grant access or require a permission prompt at launch. Configure compiled purpose strings now; call permission **getters** for state, and request permission only after a person chooses the feature. The options below are supported by the installed SDK 58 plugin source; example purpose text must truthfully describe the app feature.

| Plugin | Explicit foreground configuration | Native effect/default |
| --- | --- | --- |
| `expo-location` | `locationWhenInUsePermission: <purpose>`, `locationAlwaysPermission: false`, `locationAlwaysAndWhenInUsePermission: false`; `isIosBackgroundLocationEnabled: false`, `isAndroidBackgroundLocationEnabled: false`, `isAndroidForegroundServiceEnabled: false` | Keeps When In Use purpose, omits both Always purpose keys, and adds no location background mode/service. The three background/service flags default false for this configuration. [Plugin source](https://github.com/expo/expo/blob/sdk-58/packages/expo-location/plugin/src/withLocation.ts). |
| `expo-location` motion/precision | `motionUsagePermission: <motion purpose>` when motion activity is wanted; optional `locationFullAccuracyPermission: false` | Motion shares `NSMotionUsageDescription` with Sensors. Setting motion to false removes that key and excludes Location's motion feature; ensure plugin ordering preserves Sensors' key. `locationFullAccuracyPermission: false` omits the temporary full-accuracy purpose used by `expo-location/next`; `isIosReducedAccuracyByDefault` defaults false. [Plugin source](https://github.com/expo/expo/blob/sdk-58/packages/expo-location/plugin/src/withLocation.ts). |
| `expo-contacts` | `contactsPermission: <purpose>` | Writes `NSContactsUsageDescription`; does not authorize the app. Type is string. No iOS background option. [Plugin source](https://github.com/expo/expo/blob/sdk-58/packages/expo-contacts/plugin/src/withContacts.ts). |
| `expo-audio` | `microphonePermission: <purpose>`, `recordAudioAndroid: true`, **`enableBackgroundPlayback: false`, `enableBackgroundRecording: false`** | Microphone purpose for recording; no audio background mode/services. Playback's plugin default is **true**; recording's is false. `microphonePermission: false` disables recording permission support. Keep Camera's shared microphone purpose consistent. [Plugin source](https://github.com/expo/expo/blob/sdk-58/packages/expo-audio/plugin/src/withAudio.ts). |
| `expo-sensors` | `motionPermission: <purpose>` | Writes `NSMotionUsageDescription`. False disables motion permission support. No background mode option. [Plugin source](https://github.com/expo/expo/blob/sdk-58/packages/expo-sensors/plugin/src/withSensors.ts). |
| Battery, Network, Device, Print | No iOS purpose-string config plugin needed for basic APIs | These installed packages autolink. No user-device-name, SSID, always-location or background-audio entitlement is needed for their basic coverage. |

For Location, use `getForegroundPermissionsAsync`/`requestForegroundPermissionsAsync`; retain `ios.scope` and `ios.accuracy` (`full`/`reduced`) rather than returning only `granted`. `watchPositionAsync` is a foreground subscription; remove it when done. Do not substitute `requestBackgroundPermissionsAsync` or background tasks. [SDK 58 Location](https://docs.expo.dev/versions/v58.0.0/sdk/location/).

For Contacts, root `getPermissionsAsync`/`requestPermissionsAsync` remain supported. `accessPrivileges` distinguishes `all`, `limited` and `none`; iOS 18+ limited access is usable access to selected contacts. `Contact.presentAccessPicker()` lets people expand it. Use `Contact.getAll`/`getAllDetails`, instance methods, `presentPicker` and native forms for current APIs. Legacy operations such as root `getContactsAsync` are throwing migration stubs: import `expo-contacts/legacy` deliberately if those older functions are needed. [SDK 58 Contacts](https://docs.expo.dev/versions/v58.0.0/sdk/contacts/).

For Audio, foreground runtime mode uses `shouldPlayInBackground: false` and `allowsBackgroundRecording: false`; enable `allowsRecording` only during a recording flow. Check/request recording permission explicitly. Player/recorder objects need disposal, and interruptions and disconnected audio routes can stop playback. [SDK 58 Audio](https://docs.expo.dev/versions/v58.0.0/sdk/audio/).

On iOS, Network's `isInternetReachable` equals `isConnected`; neither proves a paired-host request will succeed. `getIpAddressAsync` on **web** calls the external ipify service, so a local-status helper should omit it. Device's user-assigned name is generic on iOS 16+ without an additional entitlement; model/OS checks should not depend on it. Battery can report unsupported/unknown in simulators. [Network](https://docs.expo.dev/versions/v58.0.0/sdk/network/), [Device](https://docs.expo.dev/versions/v58.0.0/sdk/device/), [Battery](https://docs.expo.dev/versions/v58.0.0/sdk/battery/).

## Core Haptics coverage

UIKit impact/selection/notification feedback remains useful for standard controls. Full custom pattern support uses [Core Haptics](https://developer.apple.com/documentation/corehaptics): timed transient and continuous haptic events, intensity/sharpness and envelope parameters, dynamic parameters, parameter curves, synchronized audio events/resources, and [AHAP data](https://developer.apple.com/documentation/corehaptics/representing-haptic-patterns-in-ahap-files). [Advanced players](https://developer.apple.com/documentation/corehaptics/chhapticadvancedpatternplayer) add pause/resume, seek, loop settings and playback rate. Runtime 5 implements advanced **haptic-only** patterns/playback alongside UIKit feedback. Synchronized synthesized audio, custom audio resources, and unexposed Apple operations remain additions. See [the Zorid haptics API](haptics.md) for the exact bridge rather than assuming every framework operation is exposed.

These are Apple's event-and-parameter synthesis controls. **Inference from the public API:** they do not supply a raw sample-by-sample actuator voltage/waveform interface. “Full Core Haptics” should mean coverage of the public pattern/player model, with explicit supported operations and resource types. [Hardware checks, engine resets and stopped handlers](https://developer.apple.com/documentation/corehaptics/preparing-your-app-to-play-haptics) are part of the lifecycle; do not equate a resolved bridge call with physical feedback or promise playback on unsupported hardware. If custom audio resources are added later, their file references must follow the approved-file boundary used by document APIs.

## Initial implementation batch and follow-up

Runtime 5 combines local bridges with matching official Expo modules for tasks, notes, calendars and focus:

1. Reuse RN Share/Linking, existing Camera/SecureStore, and the already installed Expo FileSystem pickers/I/O/Quick Look. Declare FileSystem directly; do not build a second native document picker. Broaden camera/microphone purpose strings for general capture.
2. Add `ZoridDevice` clipboard, photo picking/add-only saving, standalone authentication, and local notifications with categories and a response queue. The queue retains responses for consumption; it does not imply background JavaScript actions. Add advanced haptic-only Core Haptics patterns and player controls separately.
3. Add the system event editor and explicitly scoped EventKit calendar/reminder operations in the same batch. Preserve iOS 17+ write-only/full distinctions and pre-iOS-17 fallback.
4. Include installed Expo foreground location, limited-aware Contacts, Audio, Sensors, Battery, Network, Device and Print bridges in the same binary. Request personal-data permissions only from explicit feature actions. Background jobs, further Screen Time surfaces and new extension types remain separate native increments with signing/device acceptance.

Runtime 5 remains **not shipped** until native CI and delivery evidence establish otherwise. Report permission-denied, cold-start notification response, photo/file selection cancellation, interrupted authentication, calendar scope and physical haptic checks separately from successful JS export.

For every bridge, report availability and supported features; validate payloads on both sides; preserve unavailable, denied, restricted, canceled and interrupted outcomes; bound sizes/subscriptions; and document whether it runs only in the foreground app or also in a named native action context. These are API design recommendations, not additional OS capabilities. OTA apps share one installed app identity and OS grants: a JavaScript namespace is not an iOS security sandbox.

Apple's [runtime security model](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web) limits apps to their sandbox, entitlements and public services. A bridge cannot add entitlements by OTA, access arbitrary other-app data, execute downloaded native code, invoke arbitrary Swift/Objective-C symbols, or bypass system privacy prompts. Validation must include denied permissions and physical-device behavior; unit tests, typechecks and JS exports alone cannot prove these native experiences.
