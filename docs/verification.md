Directly deployed JavaScript can use the installed bridge; the Focus action bundle queues protection changes with its record transaction. Start, pause, resume and finish use the native action path. Emergency release can invalidate a selected policy when persisting the newer clear fails, preventing a pending activation from restoring that policy.

The custom-shield implementation maps all nine public `ShieldConfiguration` appearance fields, native response enums and version-gated secondary menu actions to deployed configuration. This is coverage of those configuration and response APIs, not the entire Screen Time framework or arbitrary shield layouts. The configuration datasource reads prepared state under a nonblocking shared lock without changing restrictions. Configuration and action extensions use the same global resolver when several policies could own a shield, keeping the displayed buttons and their response mapping consistent. PNG transport is bounded to 128 KiB and 1024 pixels per side; total configuration is bounded to 256 KiB. These are transport limits, not Apple layout customization APIs. SF Symbols, all 20 iPhone blur styles, alpha and dynamic light/dark colors are supported. `getShield` reads nonsensitive saved styling; opaque application tokens remain native.

Fresh local verification passed 133 Bun tests with 1,190 assertions, typecheck, lint, action-bundle freshness and iOS JavaScript export. Actual five-target prebuild passed and all 12 generated extension source references resolve. Twelve profile-archive checks and two build/signing tests pass. The native checks compile/typecheck the shield sources against Apple's SDK; build 27 now verifies a complete signed app archive with those extensions, while physical rendering remains unverified. Settings now uses a `.heavy` impact at intensity `1`. The [deployed haptics API](haptics.md) exposes UIKit impact, selection, notification, preparation, reset and supported location feedback; hardware, system settings and UIKit still determine physical feedback. Perceived Settings-opening strength and deployed feedback require a physical-device check.

Physical-device acceptance remains for individual authorization, picker appearance, actual app shielding, pause/resume/finish release, authorization revocation and background expiry. In particular, backdating a short remaining monitoring interval to satisfy Apple's 15-minute minimum needs device validation. Compilation and interval-planning checks do not establish enforcement or exact callback timing. See [Screen Time behavior and limitations](screen-time.md).

## Pause action investigation

The phone reported “The app action failed; no changes were saved” when pausing inside Zorid. This identifies a JavaScript handler exception, rather than a post-commit widget refresh failure. The exact phone-side cause remains unconfirmed because the phone was not accessible through the Mac for diagnostics.

- [Pre-fix native reproduction](https://github.com/tingkai-c/zorid-mobile/actions/runs/43054097743): the original 73 native checks passed, then the actual compiled Focus handler rejected a fresh app-side revision with the same generic error. Raw decimal JSON passed through Foundation's number conversion produced a different JavaScript number. Nine of 4,028 synthetic timestamp cases differed. The diagnostic branch deliberately retains the previous runtime and must not be shipped.
- [Corrected native checks](https://github.com/tingkai-c/zorid-mobile/actions/runs/43053834915): 99 action checks, the compiled Pause/Resume/Finish lifecycle, the new fresh-revision Pause regression, and all 4,028 numeric comparisons passed. Record reads now parse their original JSON in JavaScriptCore, matching JavaScript record semantics. Captured parser references prevent handler replacement of `JSON.parse` from changing record reads.
- Handler exceptions retain bounded own error messages without invoking ordinary message getters or custom string conversion. Unsafe values use the generic fallback. Native capability errors retain precedence. Regression checks verify record/effect rollback and the absence of a receipt for failed actions.
- All 82 JavaScript tests passed, including eight status-reporting tests, with 475 Bun assertions; typecheck, lint, generated-handler freshness and iOS export passed. Independent review found no material issue.

The stock demo creates integer timestamps, including native action timestamps. The fractional-number defect is reproduced and fixed, but does not establish why this particular phone failed. The updated native error message is needed to distinguish a stale button from other handler failures on the device. The JavaScript action bundle remains `focus-actions-1`; its code has not changed.
