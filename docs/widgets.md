# Widgets and Live Activities

Zorid uses the installed Expo SDK 58 `expo-widgets` and `@expo/ui` renderer. The Focus demo supplies SwiftUI compositions and data from JavaScript; it does not implement an arbitrary Swift runtime or a visual widget editor.

`src/native/surfaces` is the app-facing boundary:

- `getSurfaceCapability()` reports whether the native modules are installed. Availability does not imply the user has enabled Live Activities or placed a widget.
- `publishFocus({ taskTitle, status, endsAt?, elapsedSeconds? })` updates the widget and creates or updates the Focus Live Activity. `endsAt` is Unix milliseconds; status is `running`, `paused`, `completed`, or `idle`.
- `endFocus()` clears the Focus display and ends all active Zorid Focus activities.

Every update returns `{ available, widgetUpdated, activityUpdated, error? }`. UI should surface errors without rolling back the saved session. Unsupported platforms and Expo Go return an unavailable result; they do not load the SwiftUI layouts. Calls on iOS are serialized, and existing ActivityKit instances are recovered after process restart instead of creating a duplicate. Widget and Live Activity updates are separate operations: the widget may succeed even if the activity request fails.

The small and medium Home Screen widget displays the selected task and status. Running timers use SwiftUI `Text.timerInterval`; iOS renders the countdown without JavaScript tick writes. A second WidgetKit timeline entry changes the widget to complete when the end time arrives. Timeline execution remains subject to iOS scheduling. Paused/completed displays show recorded elapsed time.

The Live Activity supplies Lock Screen and Dynamic Island presentations. Its stale date is the session end time. Expiration marks the content stale and the native countdown reaches zero; it does **not** automatically persist a finished work session or call ActivityKit.end while JavaScript is suspended. The app must reconcile the session on reopening. Remote background updates through APNs are not implemented, and changes on another device cannot presently update a suspended phone's activity.

## Native configuration

The `expo-widgets` config plugin must specify:

```ts
{
  bundleIdentifier: 'app.zorid.mobile.widgets',
  groupIdentifier: 'group.app.zorid.mobile',
  enablePushNotifications: false,
  widgets: [{
    name: 'ZoridFocus',
    displayName: 'Zorid Focus',
    description: 'Your current task and focus countdown.',
    ios: {
      supportedFamilies: ['systemSmall', 'systemMedium'],
      initialLayout: './src/native/FocusWidget.tsx',
    },
  }],
}
```

`ZoridFocusActivity` is registered at runtime and is not a `widgets[]` entry. Both app and extension require matching App Group entitlements and provisioning profiles. Parent app bundle ID is `app.zorid.mobile`. Native projects are generated by Expo prebuild; edit config rather than generated Xcode files.

## Extending surfaces

Layout functions marked `'widget'` execute in an isolated runtime. They may use supported Expo UI SwiftUI components/modifiers and serialized props. They cannot read React hooks, app context, SQLite, asynchronous calls, or helpers/constants outside the function. Prepare data in the app and pass it into the layout. Keep titles/data small; ActivityKit payload limits still apply.

Existing registered widget compositions can evolve with compatible JS releases using the installed renderer. New SwiftUI primitives, native capabilities, App Group changes, extension declarations, and widget families configured in the native plugin require a new binary. A later schema-driven editor can compose the supported primitives; this foundation currently ships the concrete Focus layout only. Arbitrary custom Swift code cannot be delivered through JS OTA.

## Validation and remaining device checks

Pure tests cover expiration after process restart, timeline scheduling, paused states, and invalid timestamps. Type checking verifies the installed SDK interfaces. Native compilation, extension embedding/signing, widget gallery initial rendering, Dynamic Island sizes, countdown behavior while locked, user-disabled activities, and actual widget layout updates after direct-host OTA require a signed native build and device validation. Do not infer those behaviors from a successful JS export.

References: [Expo SDK 58 Widgets](https://docs.expo.dev/versions/v58.0.0/sdk/widgets/), [Expo UI SwiftUI Text](https://docs.expo.dev/versions/v58.0.0/sdk/ui/swift-ui/text/), [Apple ActivityKit](https://developer.apple.com/documentation/activitykit).
